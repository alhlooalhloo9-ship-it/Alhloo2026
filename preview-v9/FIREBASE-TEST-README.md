# بيئة اختبار Firebase المعزولة — Alhloo V9

## المشروع المستهدف
- Firebase Project ID: `nad-66cc2`
- ملف الإعدادات: `firebase.test.config.js`
- هذا الملف مخصص لصفحات الاختبار فقط. لا تستورده من `index.html` الإنتاجي.
- لا يوجد أي تعديل على فرع `main` أو إعدادات Firebase الإنتاجية.

## تجهيز Firebase Console يدوياً
1. افتح مشروع `nad-66cc2` وتأكد من Project ID قبل أي تغيير.
2. من Authentication > Sign-in method فعّل Email/Password.
3. أنشئ Firestore Database في وضع الإنتاج.
4. من Firestore > Rules انسخ محتوى الملف `firestore.rules` وانشره على المشروع التجريبي فقط.
5. لا تضع قواعد الاختبار في مشروع `alhlooapp`.

## تشغيل اختبار الحسابين A وB
1. شغّل الملفات من خادم static محلي أو استضافة معاينة تدعم ES modules، وليس بفتح الملف مباشرة عبر `file://`.
2. افتح `preview-v9/firebase-isolation.html`.
3. أدخل بريدين تجريبيين وكلمتي مرور منفصلتين. يمكن للصفحة إنشاء الحسابين إذا لم يكونا موجودين.
4. اضغط تشغيل الاختبار. ستنشئ الصفحة مستندات اختبار ذات أسماء عشوائية في `products` ثم تختبر القراءة الخاصة ومحاولات الوصول المتبادل وإنشاء مستند بهوية مزورة.
5. تنظف الصفحة مستندي الاختبار بعد انتهاء الاختبارات الناجحة.

## نطاق القواعد
القواعد تطابق بنية `index.html` الحالية:
- `products/{productId}`: الملكية عبر `user_id`.
- `user_carts/{uid}`: معرّف المستند هو UID ويجب أن يطابق `user_id`.
- `app_settings/{settingsId}`: الملكية عبر `user_id`.
- كل المجموعات الأخرى مرفوضة افتراضياً. لا توجد حالياً كتابة فواتير إلى مجموعة Firestore باسم `invoices` في `index.html`.

## حدود الاختبار
- ملف `preview-v9/index.html` يختبر محرك IndexedDB المحلي فقط.
- ملف `preview-v9/firebase-isolation.html` يختبر Firebase Auth وFirestore Rules بعد نشر القواعد.
- نجاح اختبار العزل لا يعني أن واجهة التطبيق الرئيسية أصبحت مرتبطة بمحرك V9؛ دمج الواجهة ومزامنتها مرحلة منفصلة.
- لا تُدخل بيانات حقيقية أو كلمات مرور مستخدمة في أي خدمة أخرى.
